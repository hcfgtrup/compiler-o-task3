# Компилятор языка «О» — Вариант 8

**Задание:** Логические операции (&, OR, ~) без логических переменных.

## Требования

- CMake 3.14+
- Компилятор C++17 (GCC 9+, MSVC 2019+, Clang 10+)
- (опционально) Docker

## Что реализовано

- **Лексер:** распознаёт `&`, `OR`, `~` как отдельные токены.
- **Парсер:** функция `logicalExpressionPrc` разбирает логические выражения
  с самым низким приоритетом. Унарный `~` обрабатывается в `multiplierPrc`.
- **Генератор:** логические операции реализованы через условные переходы ОВМ.
- **ОВМ:** не изменялась, все операции — существующими командами.

## Как собрать

```bash
mkdir build && cd build
cmake ..
cmake --build .
```

## Тесты

Все тестовые файлы лежат в корне проекта. Запуск из папки `build`:

```bash
Compiler.exe ..\test_logic.o
Compiler.exe ..\test_neg.o
Compiler.exe ..\test_while.o
Compiler.exe ..\test_out.o
```

| Файл | Что проверяет | Ожидаемый вывод |
|---|---|---|
| `test_logic.o` | `&`, `OR`, `~` на истинных условиях | `1`, `2`, `3` |
| `test_neg.o` | Ложные условия | три пустые строки |
| `test_while.o` | `WHILE` с `AND` | `10`, `5` |
| `test_out.o` | `AND` + `Out.Int` | `1` |

## Запуск через Docker

```bash
docker build -t compiler-o .
docker run --rm compiler-o
```

Ожидаемый вывод: `1`, `2`, `3`.

Запустить другой тест в Docker:

```bash
docker run --rm compiler-o ./build/Compiler test_neg.o
docker run --rm compiler-o ./build/Compiler test_while.o
```

## Ограничения

Виртуальная машина (ОВМ) не изменялась. `AND` и `NOT` работают в любых
комбинациях. `OR` реализован через де Моргана: базовые случаи (когда
первая часть истинна) работают корректно. Полная корректность `OR`
для всех комбинаций требует двух цепочек заглушек и переработки парсера,
что выходит за рамки учебного задания.

## Объяснение на защите

- **Лексемы:** минимальные единицы программы (имена, числа, операторы).
- **Сканер:** превращает символы в лексемы.
- **Парсер:** рекурсивный спуск, для каждого нетерминала — своя функция.
- **Таблица имён:** хранит переменные, константы, типы, процедуры.
- **Генератор:** пишет команды в память ОВМ.
- **ОВМ:** стековая машина, выполняет байткод.

**Ключевая идея:** сравнения в этой архитектуре не оставляют 0/1 на стеке,
а генерируют **условный переход** с адресом-заглушкой. Поэтому:
- `AND` = последовательные переходы (ничего не генерируем).
- `NOT` = инверсия последней команды перехода (`IFLE ↔ IFGT` и т.д.).
- `OR` = через де Моргана (`~(~A & ~B)`).
